# Implementation record

Baseline: F:/UE/LyraStarterGame; source UE 5.8.1 at E:/UnrealEngine.
Target repository: WangShuXian6/Lyra. Documentation uses Next.js/Fumadocs static export.

## Accepted scope

- Full Chinese Lyra curriculum grounded in local C++ and native Blueprint inspection.
- Isolated Lyra training playground and blank MMORPG prototype in F:/UE/LyraDocLabs.
- CommonUI/CommonGame/UIExtension and added MVVM teaching.
- Native UE UBT Program backend (not Drogon), PostgreSQL, account/character/session/persistence.
- Real C++, native pasteable Blueprint text, editor/Blueprint/game screenshots and provenance.
- Blueprint screenshots must use the user's BlueprintScreenshotTool at ZoomAmount=1, with all required nodes selected; retain full-resolution PNG and make it pannable at 1:1 in the docs. Screen-fit captures are not adequate for graph detail.
- User preview preference: 1920x1080, Medium scalability (group 1); preserve native 1:1 Blueprint image sizes.
- Every configuration step must be reproducible by beginners: show the creation entry, exact property values, dependencies, save/compile action, and expected result. Include genuine asset Details, Blueprint Class Defaults, Project Settings and UI binding configuration captures with field explanations, alongside graph and gameplay captures. Explain the manual operations corresponding to reproduction scripts.
- Local two-client dedicated-server validation; Pages auto deployment on main.
- Build caches use the E: SSD; retain source project paths and safe cache backups.
- MMORPG uses the engine-provided Manny/Quinn, with Lyra-style Experience/PawnData/AbilitySet initialization and modular animation layers.
- C++ owns gameplay, UI lifecycle and ViewModels; editable Widget Blueprint Designer assets own layout and style. Use CommonUI layers, event-driven MVVM and bounded layout containers instead of constructing all UI in runtime C++.
- MMORPG internationalization includes English and Simplified Chinese, a shared String Table, gather/export/import/compile pipeline, persisted culture switching, localized numbers and actual layout/focus checks.
- MMORPG ability input should follow Lyra's GameplayTag-to-granted-spec design. The final release removes the temporary fixed InputID bridge; the two tutorial abilities deliberately retain ServerOnly instant activation, without claiming the full Lyra held/released input queue or local prediction is implemented by this slice.
