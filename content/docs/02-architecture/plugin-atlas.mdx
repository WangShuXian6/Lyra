先不要背所有插件名。你要能够回答：“这个功能属于哪个插件、配置在哪个资产、谁把它接到本局游戏、退出时谁清理。”本页按**本机描述符、模块和源码**整理；引擎为 UE 5.8.1，基准工程为 LyraStarterGame，Clawtopia 不在范围内。

## 先从真实插件窗口认名字

1. 在 UE 主窗口选择 **编辑 → 插件**。这不是 Project Settings 的某个普通字段。
2. 左侧选“所有插件”，顶部搜索 `Common`。本机 Friendly Name 为 **Common UI Plugin**，直接搜不带空格的 `CommonUI` 曾得到空列表；关键词搜索更容易定位。
3. 看条目左侧复选框、名称和描述；不要点“包”来启动打包，也不要为了看配置反复切换启用状态。
4. 再比较 CommonGame、CommonUser、CommonLoadingScreen。名字都有 Common，但解决的工作不同。
![插件浏览器搜索 Common：Common UI Plugin、CommonGame、CommonLoadingScreen、CommonStartupLoadingScreen 与 CommonUser](/media/beginner/whole-guide/plugins-commonui.png)

**看图操作**：搜索框中实际输入 Common；每张卡片左侧的勾表示启用配置。名字旁 Beta/实验性是插件自身标记；它不告诉你该插件此刻是否已向当前 World 添加了组件。
![同一个功能需要经过四种连接](/media/guide-diagrams/02-architecture-plugin-atlas.svg)

**读图**：“勾了插件”只完成第一层。以 CommonUI 为例，还需要正确视口类、LocalPlayer/Policy、根布局、可激活控件、焦点和输入配置。
## 本地 Plugins 目录：逐项看职责

下表覆盖本机 **22 个项目目录中的 `.uplugin` 描述符**，包括玩法、共享库、内容和编辑器辅助工具。插件浏览器按来源/类别显示的数字可能不同，不能把目录数量当成当前 World 已激活功能数量。

| 插件 | 它负责什么 | 第一次怎么读 |
|---|---|---|
| `AsyncMixin` | 管理异步加载与回调的 C++ 辅助类 | 加载 UI 或资产时管理请求；不是自动给所有代码加线程。 [具体课程](/docs/06-ui/common-game) |
| `BlueprintScreenshotTool` | 导出蓝图图表的编辑器工具 | 用于制作教学图片；不承担玩家技能逻辑。 [具体课程](/docs/11-reference/blueprint-screenshots) |
| `CommonGame` | 按 LocalPlayer 创建 UI Policy、根布局并组合通用游戏类 | Policy 选根布局，根布局管理层；不直接设计每一个按钮。 [具体课程](/docs/06-ui/common-game) |
| `CommonLoadingScreen` | 按加载条件显示或隐藏加载界面 | 先读取未就绪原因；不要把隐藏 Widget 当成解决加载失败。 [具体课程](/docs/02-architecture/loading-online) |
| `CommonStartupLoadingScreen` | 处理游戏启动早期的预加载画面 | 启动早期画面与进入玩法时的加载界面是不同阶段。 [具体课程](/docs/02-architecture/loading-online) |
| `CommonUser` | 本地/平台用户初始化、权限和会话的通用接口 | 不等于本教程另写的账号密码、角色存档后端。 [具体课程](/docs/02-architecture/loading-online) |
| `GameplayMessageRouter` | 按 GameplayTag 在本地游戏实例内发送结构化消息 | 广播本地消息本身不会跨网络复制。 [具体课程](/docs/05-gameplay/messages-audio) |
| `GameSettings` | 定义设置项、数值来源、编辑条件与 UI 展示接口 | 音量值实际落在哪里，还要看 LyraSettingsLocal/Shared。 [具体课程](/docs/06-ui/settings-mvvm) |
| `GameSubtitles` | 媒体字幕播放、字幕显示选项与控件 | 字幕与任意 HUD 文本、伤害消息不是同一通道。 [具体课程](/docs/05-gameplay/messages-audio) |
| `GreenRoom` | 仅内容插件，本机可见 Green 资产 | 没有 C++ 模块；不要仅凭文件名判断运行中的调用关系。 [具体课程](/docs/01-start/project-map) |
| `LyraExampleContent` | 多种玩法共享的示例美术内容 | 共享资源被多个插件引用；迁移一个玩法时检查其资源依赖。 [具体课程](/docs/08-mmorpg/migration) |
| `LyraExtTool` | 本机额外的材质编辑工具与蓝图函数库 | ChangeMeshMaterials 与 EUW_MaterialTool 用于内容处理；不能称为核心战斗模块。 [具体课程](/docs/01-start/project-map) |
| `ModularGameplayActors` | 参与模块化组件扩展的基础 Actor 类 | 向组件管理器登记 Actor，使功能插件可以对它们请求组件。 [具体课程](/docs/02-architecture/initialization) |
| `PocketWorlds` | 为本地玩家管理小型关卡实例及画面捕获 | 常用于独立预览空间；不是 MMORPG 的持久化服务器分区。 [具体课程](/docs/06-ui/common-game) |
| `RedRoom` | 仅内容插件，本机可见 Red 资产 | 描述符无运行模块；从具体资产的 Reference Viewer 开始查用途。 [具体课程](/docs/01-start/project-map) |
| `RiderLink` | Rider 与编辑器之间的通信、日志、蓝图和调试支持 | IDE 辅助设施；移除它不会替你修复 Gameplay 代码。 [具体课程](/docs/01-start/environment) |
| `ShooterCore` | 射击玩法的技能、武器、HUD、组件装配与运行模块 | 本机初始 Registered，由 Experience 请求激活。 [具体课程](/docs/02-architecture/game-features) |
| `ShooterExplorer` | 依赖 ShooterCore 的冒险内容扩展示例 | 无 C++ 模块不表示没有玩法内容，继续查 Content 与依赖。 [具体课程](/docs/02-architecture/game-features) |
| `ShooterMaps` | 射击地图内容 | 地图插件依赖 ShooterCore；场景资源与规则代码分开存放。 [具体课程](/docs/01-start/first-session) |
| `ShooterTests` | 射击玩法测试及测试依赖 | 测试用例不能直接当作正常游戏规则。 [具体课程](/docs/11-reference/upgrades) |
| `TopDownArena` | 另一套俯视角玩法、内容和运行模块 | 用于比较共享基础与独立玩法；不是 ShooterCore 的改名。 [具体课程](/docs/02-architecture/game-features) |
| `UIExtension` | 让模块按标签向已有 UI 扩展点提交内容 | 扩展点是目的位置，注册的 Widget 是具体内容。 [具体课程](/docs/06-ui/extensions) |

## 以 ShooterCore 读懂描述符
源码：`Plugins/GameFeatures/ShooterCore/ShooterCore.uplugin`，本机第 13–19 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```json
"CanContainContent": true,
"IsBetaVersion": false,
"IsExperimentalVersion": false,
"Installed": false,
"ExplicitlyLoaded": true,
"EnabledByDefault": false,
"BuiltInInitialFeatureState": "Registered",
```
逐行对应到实际操作：

- `CanContainContent=true`：这个插件能带 Content 资产，所以内容浏览器开启“插件内容”后能进入它的虚拟挂载目录。
- `ExplicitlyLoaded=true`：它是显式加载的插件，不能仅凭文件存在就认为已经激活。
- `EnabledByDefault=false`：插件自身默认配置与工程/目标显式选择是不同来源；继续检查 `.uproject` 与 Game Feature 策略。
- `BuiltInInitialFeatureState=Registered`：内置 Feature 初始登记状态为 Registered。射击 Experience 的 `GameFeaturesToEnable` 再请求加载和激活它。
- `Modules` 里的 `ShooterCoreRuntime` 是模块名；插件叫 ShooterCore。找不到同名 `.cpp` 并不表示缺了整个插件。

**编辑器启用、模块加载、Feature Active、给 Actor 添加组件**是四件事。排障时按当前缺少的结果向前查，不要反复勾选插件碰运气。

## 第一次跟踪一个插件的实际使用

以 UIExtension 为练习：

1. 插件浏览器确认名字；Rider 打开 `UIExtension.uplugin`，看模块和 CommonGame 依赖。
2. 打开 `LAS_ShooterGame_StandardHUD`，找到 `W_QuickBar` 对应 `HUD.Slot.Equipment` 的注册配置。
3. 打开 `W_ShooterHUDLayout` 的 Designer，选 `ExtensionPoint_Equipment`，核对同一个标签。
4. 在 `GameFeatureAction_AddWidget.cpp` 找注册调用，再在 `UIExtensionSystem.cpp` 读匹配条件。
5. 运行相关玩法检查快捷栏；退出时查注册句柄的注销。由此得到“插件 → 配置 → 执行 → 表现 → 清理”一条完整链。

前两步只是配置层，第三步是目标容器，第四步才是执行机制。具体截图与代码逐段解释见 [UIExtension](/docs/06-ui/extensions)。

## 再深入几个容易被一笔带过的插件

### AsyncMixin：处理列表/提示的异步加载生命周期

它是 C++ 混入辅助类。实际使用者之一是 `SActorCanvas`，同时继承 SPanel、FAsyncMixin 与 FGCObject。`AddIndicatorForEntry` 异步加载提示 Widget 类，回调先确认提示对象仍有效、仍在 AllIndicators 中，再从 WidgetPool 创建/复用控件，最后 StartAsyncLoading。

这解释了“玩家已走离目标，但资源刚加载完”的情况：仅凭加载成功就显示提示，会留下过时界面。FAsyncMixin 管请求生命周期，AllIndicators 判断业务上是否仍需要这条提示，两项都要考虑。

阅读 `Plugins/AsyncMixin/Source/Public/AsyncMixin.h` 顶部示例：CancelAsyncLoading → AsyncLoad 多个资源 → StartAsyncLoading。注释说明回调按请求顺序触发；它不是“任何 Lambda 都自动切到工作线程”的工具。调试入口为 `LogAsyncMixin Verbose`，只在需要诊断时开启。

### PocketWorlds：按本地玩家复用小型关卡实例
源码：`Plugins/PocketWorlds/Source/Private/PocketLevelSystem.cpp`，本机第 10–36 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```cpp
UPocketLevelInstance* UPocketLevelSubsystem::GetOrCreatePocketLevelFor(ULocalPlayer* LocalPlayer, UPocketLevel* PocketLevel, FVector DesiredSpawnPoint)
{
	if (PocketLevel == nullptr)
	{
		return nullptr;
	}

	float VerticalBoundsOffset = 0;
	for (UPocketLevelInstance* Instance : PocketInstances)
	{
		if (Instance->LocalPlayer == LocalPlayer && Instance->PocketLevel == PocketLevel)
		{
			return Instance;
		}

		VerticalBoundsOffset += Instance->PocketLevel->Bounds.Z;
	}

	const FVector SpawnPoint = DesiredSpawnPoint + FVector(0, 0, VerticalBoundsOffset);

	UPocketLevelInstance* NewInstance = NewObject<UPocketLevelInstance>(this);
	NewInstance->Initialize(LocalPlayer, PocketLevel, SpawnPoint);

	PocketInstances.Add(NewInstance);

	return NewInstance;
}
```

PocketLevel 为空就返回；已有实例的 LocalPlayer 和 PocketLevel 都匹配就复用。循环还累积 Bounds.Z，为后续实例安排竖直偏移，避免多个预览空间重叠。函数后半部 NewObject → Initialize → 保存实例。

`UPocketLevel` 数据资产的 **Streaming → Level** 是地图软引用，**Bounds** 描述空间范围；实例提供 StreamIn、StreamOut、AddReadyCallback/RemoveReadyCallback。准备预览时要等待 Ready，再显示捕获结果。这里是在游戏世界中管理小型流送空间，不提供账号租约、跨服或数据库隔离。

新手阅读顺序：PocketLevel.h 的两个字段 → PocketLevelSystem.cpp 的复用键 → PocketLevelInstance.cpp 的加载/显示回调。先找到项目中实际引用该资产的预览控件，再修改自己的副本，不能只启用插件就期待主菜单自动多出角色预览。

void FCommonStartupLoadingScreenModule::StartupModule()
{
	// No need to load these assets on dedicated servers.
	// Still want to load them in commandlets so cook catches them
	if (!IsRunningDedicatedServer())
	{
		PreLoadingScreen = MakeShared<FCommonPreLoadScreen>();
		PreLoadingScreen->Init();

			FPreLoadScreenManager::Get()->RegisterPreLoadScreen(PreLoadingScreen);

### TopDownArena：同一相机基础如何服务另一种玩法

在 Content Browser 开启插件内容，选 **TopDownArena Content → Game**，双击 `CM_ArenaFramingCamera`。纯数据蓝图直接显示默认值；展开 Default Pivot Rotation，比较下图与 Shooter 的 CM_ThirdPerson。
![TopDownArena 相机实拍：Arena Width/Height=1600，Y 旋转=-66，FOV=80](/media/beginner/whole-guide/topdown-camera.png)

**看图操作**：窗口父类为 LyraCameraMode_TopDownArenaCamera。这里根据竞技场范围取景，而非第三人称肩后偏移；Bounds Size to Distance 是范围尺寸到相机距离的曲线。图显示当前曲线控件，不把缩略曲线上的刻度当成所有实际关键帧值。
源码：`Plugins/GameFeatures/TopDownArena/Source/TopDownArenaRuntime/Private/LyraCameraMode_TopDownArenaCamera.cpp`，本机第 14–30 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```cpp
void ULyraCameraMode_TopDownArenaCamera::UpdateView(float DeltaTime)
{
	FBox ArenaBounds(FVector(-ArenaWidth, -ArenaHeight, 0.0f), FVector(ArenaWidth, ArenaHeight, 100.0f));

	const double BoundsMaxComponent = ArenaBounds.GetSize().GetMax();

	const double CameraLoftDistance = BoundsSizeToDistance.GetRichCurveConst()->Eval(BoundsMaxComponent);

	FVector PivotLocation = ArenaBounds.GetCenter() - DefaultPivotRotation.Vector() * CameraLoftDistance;

	FRotator PivotRotation = DefaultPivotRotation;

	View.Location = PivotLocation;
	View.Rotation = PivotRotation;
	View.ControlRotation = View.Rotation;
	View.FieldOfView = FieldOfView;
}
```

代码用 `(-ArenaWidth,-ArenaHeight)` 到 `(ArenaWidth,ArenaHeight)` 构造范围。因此截图 Width=1600 在这个函数中是半范围，X 方向总宽度为 3200；不要只凭字段英文把它理解成整场宽度。取最大尺寸后求曲线值，沿 DefaultPivotRotation 的反方向拉开相机，设置 View 的位置、旋转和 FOV。

继续打开 `/TopDownArena/Game/HeroData_Arena` 与 `/TopDownArena/System/Experiences/B_TopDownArenaExperience`，记录 PawnData、相机与 Feature。对照射击 Experience 的同类字段，就能理解复用的是装配方式，而不是所有模式都使用步枪/肩后相机。移动和属性的专用代码位于 TopDownArenaRuntime 的 TopDownArenaMovementComponent 与 TopDownArenaAttributeSet。
