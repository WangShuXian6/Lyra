本篇供学习和实战时反复查阅。先描述症状发生在哪个工程、World、网络实例和初始化阶段，再选择检查点。不要一遇到问题就同时重装插件、清缓存、换 API；一次改变多个变量会抹掉故障原因。

## 快速入口

- [按现象排障](/docs/11-reference/troubleshooting)：加载、角色、输入、技能、武器、UI 和打包的第一检查点。
- [蓝图原始比例截图](/docs/11-reference/blueprint-screenshots)：本机插件身份、5.8.1 编译修复、完整图导出和真实验证结果。
- [性能定位](/docs/11-reference/performance)：固定测量场景，分开客户端、服务器、UI 与复制成本。
- [升级与证据](/docs/11-reference/upgrades)：维护来源哈希、版本边界、蓝图图文与验证记录。
- [文档站与 Pages 发布](/docs/11-reference/publishing)：检查两套静态路径，通过 main 自动部署，维护提交和回退记录。
- [术语速查](/docs/11-reference/glossary)：按英文类名查中文解释和教程入口。

## 一份有用的故障记录

```text
版本 / 工程：
地图 / Experience / 来源：
服务器或客户端 / LocalRole：
复现步骤：
预期与实际结果：
首个错误日志：
最后一次有效状态 / 下一条件：
尝试过的单一修改与结果：
```

本课程源码与配置分析以 2026-09-13 的本机 UE 5.8.1 工作副本为基准。源码已核对、素材已导出、测试已执行是三种不同声明；阅读本篇的证据说明，可以判断一条结论适用于哪个范围。

完成一个修复后，除了原成功场景，还验证一次退出、重新进入或异常中断。Lyra 的许多问题来自初始化与清理不同步，第二次进入往往比第一次更能暴露问题。
