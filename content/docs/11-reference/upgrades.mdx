## 学习目标与前置条件

本课程分析的是本机 UE 5.8.1 Lyra 工作副本，不宣称它与任何公开发行包逐字一致。核对日期 2026-09-13。目标是升级后能明确指出哪些教程结论仍成立，哪些需要重新验证。

源码证据保存在仓库 `source-evidence/lyra-references.json`，包括引擎版本、关键源文件 SHA-256、相关章节、符号位置和已核对资产包路径。哈希说明某次读到的文件内容；它本身不是版权来源证明或运行成功证明。

## 源码、图表、编译与运行分别记录

| 证据 | 可以证明 | 不能证明 |
|---|---|---|
| 源文件与配置检查 | 声明、调用、默认规则在该版本存在 | 某条运行分支本次已执行 |
| 编辑器图/节点导出 | 资产图的实际节点与连接 | 任意工程粘贴均可编译 |
| 编译/构建日志 | 指定目标或蓝图结构在当前依赖下可编译 | 同类型参数连接符合玩法含义 |
| 实际运行记录 | 指定配置和流程本次观察到预期行为 | 所有平台、所有网络条件都正确 |

截图保留来源包路径、图名、版本与说明。蓝图全图使用真实编辑器导出，不用示意节点图伪装官方截图；文本中包含的外部变量和资产引用必须随教程说明。

尤其检查**同类型但不同含义的引脚**。两个 float 分别表示 Direction 与 Speed 时，交换后仍能编译；Dash 的两个 Rotator 交换后，角度差符号改变但节点类型仍合法。复核顺序应是源资产字段/轴名称 → `LinkedTo` 的真实来源 → 固定输入下的输出 → 游戏画面，而不是到 Compile 成功就结束。连线后的输入 Pin 还可能保留序列化 DefaultValue，那不代表运行时忽略已连接的数据。

## 操作步骤：升级一个小版本

1. 保留旧引擎和旧基准工程，创建独立升级副本。记录引擎 Build.version 与当前文档仓库提交。
2. 先升级和构建未加入教学增量的基准副本，确认官方内容能够运行；这样可以将引擎/示例兼容问题与自定义代码问题分开。
3. 对照来源清单检查 Source、Config、插件描述符变化。优先看 GAS API、输入用户设置、Game Features 生命周期、UI 路由和复制 API。
4. 按 Editor → Client/Server → Backend Program 的目标分别验证；每个目标依赖集合不同。
5. 重新编译受影响蓝图，检查重定向、废弃节点与资产扫描，再验证根本行为：进入玩法、输入、开火、死亡重生、UI 返回和持久化。
6. 更新证据日期、哈希、截图及章节说明，在部署前执行静态站检查和深层链接测试。

## 本机需要特别区分的内容

ModelContextProtocol、AllToolsets、ToolsetRegistry、RiderLink、LyraExtTool 和用户新增的 BlueprintScreenshotTool 与当前工作工具有关。不要让教学客户端依赖编辑器截图工具，也不要把工具插件新增的资产当作官方玩法设计依据。

本机源码里 AbilitySpec 标签使用 `GetDynamicSpecSourceTags()`；从旧文章复制 `DynamicAbilityTags` 时应检查新的接口。类似迁移要通过完整构建和蓝图编译确认，不应仅凭搜索替换就宣告完成。

本地化也要区分来源：官方 Lyra 已有 GameSettings 语言选项和 Game 等翻译目标；教程新增的是 MMORPG 自己的界面词条、MMO Target 和 ViewModel 刷新链。UE 编辑器菜单的语言、游戏 Culture、实际 Stage 的 locres 与网站中文正文是四个不同观察点。更换任一项，都不能据此推断另外三项已通过。

### 不会读 diff 时先从一行 API 变化开始

在 Rider 打开同一文件的版本比较：红色通常表示删除，绿色通常表示新增；同时看函数声明和调用者。比如 AbilitySpec 的标签读取应对照本机 GetDynamicSpecSourceTags 接口，不把旧文章中的字段名替换后就认为所有语义一致。

PowerShell 可用下列只读命令记录文件内容哈希：

```powershell
Get-FileHash 'F:/UE/LyraStarterGame/Source/LyraGame/AbilitySystem/LyraAbilitySet.cpp' -Algorithm SHA256
```

输出的 Hash 对应文件字节；换行也会改变它。哈希没有说明“哪一行改了”，所以接着查看 diff，定位到资产字段或运行分支。不要为了让旧清单通过，直接把新哈希填进去而不复核材料。

## 预期结果与练习

最终升级记录应能回答：升级了什么、使用哪个版本、通过哪些构建和运行场景、剩余哪些限制。若某个验证未执行，明确写“未执行”和原因，不写“应当可用”作为验收结论。

练习：选择 ExperienceManager 或 HeroComponent，与另一合法获得的版本进行差异比较，挑一个会影响教程操作的变化，补一条兼容说明。数据库迁移另按后端章节管理，不与 UE 资产重定向混为同一迁移。
