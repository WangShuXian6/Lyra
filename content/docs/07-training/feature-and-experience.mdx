## 学习目标与前置条件

能够解释为什么“插件文件夹存在”不等于“玩法已激活”。先在官方 `/ShooterCore/Maps/L_ShooterGym` 跑通一次射击模式，确认角色、HUD、武器和机器人正常。

本节依据 UE 5.8.1 本机源码，核验日期 2026-09-13。关键文件为 `Source/LyraGame/GameModes/LyraExperienceDefinition.h`、`LyraExperienceManagerComponent.cpp`、`LyraWorldSettings.h` 和 `Character/LyraPawnData.h`。

## 一、创建插件

在实验工程的 Game Features 插件目录中创建 `TrainingRange`，启用内容，声明依赖 `ShooterCore` 与地图直接引用的 `LyraExampleContent`，初始状态为 Registered。配套 `.uplugin` 为：

```json
{
  "FileVersion": 3,
  "Version": 1,
  "VersionName": "1.0",
  "FriendlyName": "Lyra Tutorial Training Range",
  "Category": "Game Features",
  "CanContainContent": true,
  "EnabledByDefault": false,
  "ExplicitlyLoaded": true,
  "BuiltInInitialFeatureState": "Registered",
  "Modules": [
    {
      "Name": "TrainingRangeVerification",
      "Type": "Runtime",
      "LoadingPhase": "Default",
      "TargetConfigurationAllowList": [ "Development" ],
      "TargetAllowList": [ "Game", "Client", "Editor" ]
    }
  ],
  "Plugins": [
    { "Name": "ShooterCore", "Enabled": true },
    { "Name": "LyraExampleContent", "Enabled": true },
    { "Name": "GameplayAbilities", "Enabled": true },
    { "Name": "CommonUI", "Enabled": true },
    { "Name": "CommonLoadingScreen", "Enabled": true }
  ]
}
```

Registered 让编辑器能够发现插件资产。进入 Experience 时，Experience Manager 才请求将需要的玩法功能激活。插件依赖解决加载顺序；Experience 的 `GameFeaturesToEnable` 表达这次游戏需要的功能。

如果使用上一节的 `prepare-labs.ps1 -Lab Training`，脚本会在训练工程 `.uproject` 的 **Plugins** 数组中追加 `{ "Name": "TrainingRange", "Enabled": true }`。手工复制文件时也要核对这条项目引用：`EnabledByDefault=false` 不会替你启用它，`BuiltInInitialFeatureState=Registered` 是启用后的 Feature 初始状态。先放齐下面提到的 `Source` 与 Editor 工具源码，按第四节完成构建，再打开训练工程；在 **Edit → Plugins** 搜索 TrainingRange 核对启用，在 Content Browser 勾选 **Show Plugin Content** 后应出现 TrainingRange Content。

配套版本另外包含原创 `TrainingRangeVerification` 模块，用于[实际归档程序验收](/docs/07-training/multiplayer-and-package#归档程序的原生运行验收)。因此复制 `.uplugin` 时也要复制同目录 `Source`，再构建完整目标，不能只添加 Modules 字段。Development Editor 会编译验收主体以提前核对 C++ API，但启动时明确拒绝 Editor/PIE 执行；Development 游戏只有使用 Cook 内容且收到显式验收开关才注册 ticker，正常训练玩法不依赖它。该模块已于 **2026-09-13 16:34 UTC** 随完整 `LyraEditor Win64 Development` 目标编译、链接成功，见 `verification/training-editor-final-build.json`。最终导航地图于 **20:39 UTC 完成 LyraGame Development 构建、重新 Cook、Stage 与归档**，同一归档程序随后两次原生运行均 **11/11 通过并正常退出**。证据与首轮音频队列错误、复测边界见[打包验收](/docs/07-training/multiplayer-and-package#本次-package-与两次归档运行结果)；已有 PIE 报告仍保留各自范围。

## 三、注册与选择 Experience

创建 `/TrainingRange/TrainingRange`，类型为 `GameFeatureData`。在 Primary Asset Types to Scan 中加入：类型 `LyraExperienceDefinition`、基类 `LyraExperienceDefinition`、勾选 Has Blueprint Classes、目录 `/TrainingRange/Experiences`、Cook Rule 为 Always Cook。再加入类型 `Map`、基类 `World`、不勾选 Has Blueprint Classes、目录 `/TrainingRange/Maps`，同样使用 Always Cook。

打开 `L_TrainingRange`，在 World Settings 的 Default Gameplay Experience 中选择 `B_TrainingRange`。这项设置存储的是 Experience **类的软引用**。不要把 `LyraUserFacingExperienceDefinition` 当成相同的数据类型；后者负责前端选择界面与创建会话。

新建 GameFeatureData 的具体入口是 TrainingRange Content 根目录空白处右键 → **Miscellaneous → Data Asset**，在类型选择器搜索 **GameFeatureData**，命名为 **TrainingRange**。打开资产后展开 Primary Asset Types to Scan，每个类型各新增一行，再展开 Directories 新增目录项；Rules 下把 Cook Rule 选为 Always Cook。地图扫描的 Asset Base Class 是 **World**，不是 LyraExperienceDefinition。配置后点 Save，这个数据资产没有 Compile 按钮。

地图配置从 **Window → World Settings** 进入，搜索 Default Gameplay Experience，选择 `B_TrainingRange` 后保存当前地图（Ctrl+S）。关闭再打开地图，确认字段仍指向训练副本，然后才启动 PIE。配置截图要同时保留地图标签页和该字段，单独截一个 `B_TrainingRange` 文件名不能证明地图保存了引用。

## 四、脚本复现

脚本需要配套的 **LyraDocTools Editor 插件**。`prepare-labs.ps1 -Lab Training` 会把 `examples/LyraTraining` 里的教学文件复制到实验工程，包括 `Plugins/LyraDocTools`、`Plugins/GameFeatures/TrainingRange` 和 `prepare_training.py`。若实验工程早于插件创建，请先复制这些新增教学文件；先保留自己对实验工程的修改，再决定是否重跑整个复制脚本。

`LyraDocTools` 是普通 Editor 插件，与内容 Game Feature `TrainingRange` 分工不同。它依赖已有 `LyraGame` 模块，提供 `replace_ability_in_set`、`configure_training_feature`、`configure_training_world` 和 `build_training_navigation` 等原生方法。在本机 5.8.1，Python 读取 AbilitySet 后得到的分离结构值不能直接修改 `EditDefaultsOnly` 字段，结构构造也不接受这些命名参数；原生方法通过资产所属数组的反射属性修改能力，保留 Input Tag 和等级。资产扫描配置使用原生 `FPrimaryAssetTypeInfo` 构造函数。

首次执行 Python 前，保存工作并正常关闭所有使用同一引擎且存在 Live Coding 会话的编辑器，构建完整训练场 Editor 目标：

```powershell
& E:/UnrealEngine/Engine/Build/BatchFiles/Build.bat `
  LyraEditor Win64 Development `
  -Project=F:/UE/LyraDocLabs/LyraTraining/LyraStarterGame.uproject `
  -EnablePlugin=LyraDocTools -EnablePlugin=TrainingRange `
  -NoUBA -MaxParallelActions=3 -WaitMutex
```

确认构建成功后，执行资产生成。`EnablePlugin` 是上面 UBT 的参数；下面编辑器的 `EnablePlugins` 接受逗号分隔列表，不要混淆：

```powershell
& E:/UnrealEngine/Engine/Binaries/Win64/UnrealEditor-Cmd.exe `
  F:/UE/LyraDocLabs/LyraTraining/LyraStarterGame.uproject `
  -run=pythonscript `
  -script=F:/UE/LyraDocLabs/LyraTraining/prepare_training.py `
  '-EnablePlugins=LyraDocTools,PythonScriptPlugin,EditorScriptingUtilities' `
  '-ini:Engine:[DevOptions.Shaders]:NumUnusedShaderCompilingThreads=1,[DevOptions.Shaders]:NumUnusedShaderCompilingThreadsDuringGame=1,[DevOptions.Shaders]:bForceUseSCWMemoryPressureLimits=False,[SystemSettings]:r.ForceAllCoresForShaderCompiling=0' `
  '-ini:EditorPerProjectUserSettings:[/Script/ModelContextProtocolEngine.ModelContextProtocolSettings]:bAutoStartServer=False' `
  -unattended -NullRHI -LiveCoding=false -Multiprocess -corelimit=3
```

完整准备使用上面的独立 commandlet。导航步骤调用 `LyraDocToolsLibrary.build_training_navigation(world)`：等待异步加载与资产编译完成后，仅释放该训练 World 的 `AsyncLoadLock`，拒绝其他阻塞锁，再调用同步 `UNavigationSystemV1::Build()`。随后对三个原有拾取点实际投影，全部成功才保存地图。上面的 `-corelimit=3` 与 Shader INI 将本机编译 worker 限制为 2；`-Multiprocess` 避免启动时自动触发 SDK 验证的额外 UBT。

图形编辑器中的 **Build → Build Paths / BUILDPATHS** 仍按前节手工使用；不要把它放进 Python commandlet。本机 5.8.1 的 `FEditorBuildUtils::EditorBuild()` 包装还会访问图形进度窗口，曾在无界面 commandlet 中产生原生异常。该失败保留在 `verification/training-prepare-navigation-failure.json`；修正后的 helper 已随完整 LyraEditor 目标编译通过。

需要自己复验时，把上面同一条 commandlet 命令中的 `-script` 改为 `F:/UE/LyraDoc/scripts/verify-training-prepare.py`。它先检查 repo/lab 的准备源码 SHA 相同，并保留每一轮报告。早先重复 `load_level` 导致 World GC 失败的 `verification/training-prepare-repeat.json` 仍保留；现行源码通过比较完整 World 路径跳过同地图重载。不能清空全部引擎对象、删除地图或只改报告来规避失败。

## 预期结果与排障

打开地图后，World Settings 指向训练 Experience；PIE 的角色仍能移动、开火和冲刺。Rider 在 `ULyraExperienceManagerComponent::OnExperienceLoadComplete` 处断点，确认实际加载的是训练 Experience。只看地图名称不能证明装配数据已替换。

如果出现找不到 Primary Asset，先检查 GameFeatureData 的扫描目录和 Has Blueprint Classes，再看 `LogGameFeatures` 是否已注册插件。如果角色出生但没有能力，继续追 `DefaultPawnData` 和 `AbilitySets`，不要用 Level Blueprint 重复授予技能来掩盖初始化错误。

如果 Python 提示没有 `LyraDocToolsLibrary`，先检查训练场 `Plugins/LyraDocTools` 是否存在、完整 Editor 目标是否已编译，以及本次 commandlet 是否启用了该插件。只有复制 `.h/.cpp` 文件还不足以让 Python 看到反射类。
