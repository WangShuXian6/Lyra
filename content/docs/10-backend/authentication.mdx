## 学习目标与前置条件

能从接口请求追踪到 SQL 条件，解释为什么客户端不能保存角色、旧票据不能反复进入服务器。需要已经初始化数据库并了解 HTTP Bearer 头。本篇对应教学后端 v1，源码核对日期 2026-09-13。

## 注册和登录

客户端向 `POST /v1/auth/register` 发送用户名和密码，成功获得 `accountId`；向 `POST /v1/auth/login` 发送同样的字段，成功获得 `token` 和 `expiresIn`。用户名转成小写，只接受 3–32 个英文字母、数字和下划线；密码长度为 12–128 个字符。下面的密码仅用于讲解请求格式：

```json
{"username":"tutorial_user","password":"Use-a-unique-long-password"}
```

密码使用 libsodium `crypto_pwhash_str` 保存自描述的 Argon2id 哈希。验证使用 `crypto_pwhash_str_verify`，不自己实现密码哈希算法，也不保存密码原文。未知账号同样执行密码 KDF，以减少“账号不存在”路径与“密码错误”路径的耗时差异。

登录令牌来自 32 字节密码学随机数，编码为 64 个十六进制字符。数据库只存摘要，原令牌只交给客户端。每次成功登录在账号行锁保护下替换该账号已有登录会话，并删除此前尚未消费的入服票据；新会话有效期为 24 小时。客户端后续请求通过请求头携带令牌：

```text
Authorization: Bearer <login-token>
Content-Type: application/json
```

退出登录调用 `POST /v1/auth/logout`。它删除当前登录会话和未消费的入服票据。已进入游戏的租约需要游戏服务器完成最终保存和释放；撤销登录会话与硬踢在线角色是不同业务动作。

角色列表、建角、申请票据和退出共用同一段授权流程：先通过令牌摘要找到账号，再开始事务、锁定账号行，最后在锁内重新查询会话有效性。第一次查询只负责找到要锁定的账号。若请求正在等锁，另一个请求已经完成退出或替换登录，锁内查询必须拒绝旧会话；不能继续沿用等待前的认证结果。有效期复查使用 `clock_timestamp()`，让等待期间发生的过期也生效。

## 申请并兑换入服票据

客户端首先调用 `GET /v1/characters`，或者用 `POST /v1/characters` 创建角色，然后提交：

```http
POST /v1/join-ticket
Authorization: Bearer <login-token>
```

```json
{"characterId":"<owned-character-uuid>","serverId":"local-1"}
```

后端确认角色归属于登录账号，确认该账号没有未过期的游戏租约，然后返回 `ticket`、`expiresIn:60` 和 `address`。每次申请会替换该账号尚未消费的旧票据，因此 UI 应禁用重复点击并保存最新响应。

游戏服务器拿到票据后，使用单独配置的 `MMO_SERVER_SECRET` 调用 `POST /v1/server/consume-ticket`。客户端令牌无法调用服务器接口。票据记录同时绑定 `character_id` 和 `server_id`；仅知道另一个角色 UUID 不足以冒充它。

```json
{"ticket":"<one-use-ticket>","serverId":"local-1"}
```

兑换先无锁读取票据以定位账号，再锁定账号行，随后通过 `SELECT ... FOR UPDATE` 重新检查票据归属、服务器、未消费状态和实际过期时间。最后清理这个账号已过期的旧租约，创建新租约，并标记票据已消费。入服相关操作统一按“账号 → 票据 → 租约”顺序取得锁，避免申请新票据和兑换旧票据互相等待。成功响应同时返回 `leaseToken` 和完整 `character`。多个并发请求只能有一个成功。

这里的先后顺序由取得账号锁决定。新票据申请先完成时，旧票据随后兑换得到 401；兑换先完成时，随后申请得到 409 `already_online`；退出先完成时，正在等待的旧会话请求和旧票据兑换得到 401。源码定位在 `Source/MMOPersistence/Private/MMOPersistence.cpp` 的 `FMMOPersistence::Execute`，并发复现见 [接口验收](/docs/10-backend/run-and-test)。

## 游戏租约

| 凭据 | 谁持有 | 有效期 | 用途 |
| --- | --- | --- | --- |
| 登录令牌 | 客户端 | 24 小时 | 管理自己的角色并申请票据 |
| 入服票据 | 客户端短暂持有，再交给游戏服务器 | 60 秒，消费一次 | 将登录身份交换成在线角色 |
| 游戏租约 | 游戏服务器 | 120 秒，可续租 | 加载、保存和释放指定角色 |
| 服务密钥 | 后端与可信游戏服务器 | 配置管理 | 允许调用服务器专用接口 |

协议提供 `/v1/server/heartbeat`；成功加载和保存也续租。当前教学游戏在 `AMMOGameMode::PeriodicSave` 中每 15 秒提交存档，以保存请求维持租约，没有额外的 30 秒心跳定时器。请求包含 `characterId`、`leaseToken` 和 `serverId`；每次访问都检查三者和数据库过期时间。过期租约不能靠迟到心跳复活，避免旧进程在新玩家入服后恢复写权限。

掉线后正常流程是最后保存、释放。服务器崩溃时，租约自然到期后可再次入服；崩溃之前未提交的战斗变化不在恢复保证内，因此仍需要周期保存。

## 失败状态与 UI 行为

| HTTP / 错误码 | 原因 | 客户端或服务器动作 |
| --- | --- | --- |
| 401 `unauthorized` | 登录或服务身份无效 | 客户端返回登录流程；服务器检查服务配置 |
| 401 `invalid_ticket` | 票据过期或已消费 | 客户端申请新票据 |
| 404 `character_not_found` | 角色不存在或不属于该账号 | 刷新角色列表 |
| 409 `already_online` | 账号已有活动租约 | 显示账号已在线，等待正常离服或租约到期 |
| 403 `invalid_lease` | 租约无效、已释放或过期 | 停止角色持久化写入，并结束该游戏会话 |
| 503 `busy` | 工作队列满 | 退避重试，保持按钮状态清晰 |

### 一次性随机令牌的实际生成代码
源码：`examples/MMORPG/Source/MMOPersistence/Private/MMOPersistence.cpp`，本机第 47–51 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```cpp
FString Token()
{
    unsigned char Bytes[32]; char Hex[65]; randombytes_buf(Bytes,sizeof(Bytes));
    sodium_bin2hex(Hex,sizeof(Hex),Bytes,sizeof(Bytes)); return UTF8_TO_TCHAR(Hex);
}
```

32 个随机字节编码成 64 个十六进制字符；字符更长只是编码表示，不意味着随机量翻倍。Hex 额外留一位用于字符串结束符。后续 Hash 函数产生数据库用于查找的摘要，不能用密码哈希字符串当作同一个登录 token。

### 为什么取得锁以后还要再验证一次

设请求 A 先查到登录有效，但等待账号锁；请求 B 在此期间完成退出。A 拿到锁后若沿用旧结论，可能给已退出的会话发新票据。本机在锁内重新查询会话，并用实际时间检查过期，才继续角色/票据操作。

| 调用 | 谁发起 | 返回成功后下一步 |
|---|---|---|
| register | 客户端 | 取得 accountId 后登录 |
| login | 客户端 | 保存本次 token，读取角色列表 |
| join-ticket | 客户端 | 用返回地址和最新票据连接 UE Server |
| consume-ticket | 游戏服务器 | 装载角色快照，并等 Experience 就绪 |

**练习**：按本章测试脚本执行重复兑换、跨账号角色与已在线账号请求。记录 HTTP 状态和 error.code；不要只写“失败了”。这些是接口合约检查，不是让 UI 自己决定授权。

## 预期结果、排障与练习

用测试脚本分别尝试错误密码、越权角色、客户端令牌调用服务器接口、重复兑换票据、重复在线和过期租约。它们应返回结构化错误，数据库中的角色状态保持原值。

练习：说明“点击两次进入世界”时 UI 与后端各应如何处理；如果第一次兑换成功但响应丢失，当前 v1 会让客户端等待租约过期后重新申请。本课程没有实现跨请求找回租约的恢复协议，部署时应明确这个体验边界。

密码处理依据 [libsodium 密码哈希接口](https://doc.libsodium.org/password_hashing/default_phf)，令牌随机数依据 [libsodium 随机数接口](https://doc.libsodium.org/generating_random_data)。
