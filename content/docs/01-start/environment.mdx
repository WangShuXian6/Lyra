本教程面向 UE 新手。Actor 是能放进关卡的对象，蓝图是 UE 的可视化类与脚本，PIE 是在编辑器内运行游戏的预览。你不需要先通读 GAS；先认识界面、运行游戏，再沿着一个可见行为查找代码。

首次构建先完成[关闭 Live Coding 图解](/docs/01-start/live-coding)。不熟悉内容浏览器、类默认值或 Rider 查找时，按[步枪导航的逐步截图](/docs/01-start/project-map#操作步骤以步枪为线索)操作。

## 学习目标与前置条件

本机基准工程为 `F:/UE/LyraStarterGame/LyraStarterGame.uproject`，引擎为 `E:/UnrealEngine`。`Engine/Build/Build.version` 实际记录版本 **5.8.1**，`CompatibleChangelist` 为 `55116800`。核对日期：2026-09-13。本文核对了配置与源码；具体机器上的运行结果需按下面步骤确认。

`.uproject` 中的 `EngineAssociation` 是本机注册引擎的 GUID，不是版本号。不要把它机械改成 `5.8`：那可能选择另一套 Launcher 引擎。版本升级时保留原工程与独立副本。

## 操作步骤

1. 新读者从 [Epic 的 Lyra 示例入口](https://dev.epicgames.com/documentation/unreal-engine/lyra-sample-game-in-unreal-engine) 获取与自己引擎相符的示例。本课程的逐行分析以本机版本为准。
2. 用 Rider 打开 `.uproject`，等待 Unreal 工程模型建立。配置选择 **Development Editor / Win64**，目标为 **LyraEditor**。
3. 确认打开的是 `F:/UE/LyraStarterGame/LyraStarterGame.uproject`。后续训练副本也叫 LyraStarterGame，窗口标题只能辅助识别，必须同时核对完整工程路径。内容浏览器启用 **Show Plugin Content**，否则看不到 ShooterCore、ShooterMaps 等插件资产。
4. 查看 Output Log 是否存在缺失模块、加载失败或编译错误。仅有编辑器窗口出现不等于项目加载完成。
5. 后续修改只在 `F:/UE/LyraDocLabs` 的实验工程完成；基准工程用于查阅和对照。

## 构建目标到底是什么

| 目标 | 用途 | 本教程中的位置 |
|---|---|---|
| Editor | 编辑资产、PIE、蓝图编译 | LyraEditor Win64 Development |
| Game / Client | 玩家运行的游戏进程 | 训练场和 MMORPG 客户端 |
| Server | 独立游戏服务器，无玩家窗口 | 网络权威逻辑与角色存档联调 |
| Program | 专用工具或服务程序 | 后续独立账号与持久化后端 |

源码引擎允许检查和构建引擎模块；Launcher 引擎主要使用已编译的安装构建。两者的可构建目标与本机构建环境存在差异，不能把“能编译 Editor”直接当作“能编译独立 Server 或自定义 Program”的证明。

完整构建命令如下。在执行前先保存工作，检查所有使用同一引擎的编辑器是否存在活动 Live Coding 会话，再正常关闭相关编辑器。

```powershell
& 'E:/UnrealEngine/Engine/Build/BatchFiles/Build.bat' `
  LyraEditor Win64 Development `
  '-Project=F:/UE/LyraStarterGame/LyraStarterGame.uproject' `
  -WaitMutex
```

Live Coding 适合支持热更新的实现变化；添加模块、改变反射声明或类型布局时应做完整构建。另一工程的编辑器也可能占用同一套引擎的 Live Coding 状态。

## 原理与源码定位

阅读 `Source/LyraGame/LyraGame.Build.cs`，区分模块依赖和 `.uproject` 中的插件启用。启用 GameplayAbilities 插件不会自动给你的新 C++ 模块添加头文件和链接依赖；相反，加入模块依赖也不会替你创建 AbilitySet 或配置 PawnData。

本机启用了 `ModelContextProtocol`、`ToolsetRegistry`、`AllToolsets` 等编辑器工具。这些是当前工作环境的一部分，不应讲成 Lyra 核心玩法的必需依赖。

## 中文编辑器与游戏语言分别设置

教程保留英文菜单名、字段名、类名和资产名，方便与源码和截图逐项对应。中文编辑器中可以从 **编辑 → 编辑器偏好设置 → 通用 → 区域和语言** 找到相应入口；英文为 **Edit → Editor Preferences → General → Region & Language**。**Editor Language** 控制编辑器显示语言，**Preview Game Language** 控制游戏预览语言，两项不要混用。需要与本章截图一致时可选择英文编辑器界面，并按提示重启。

中文显示应通过文本与翻译资源实现，不要把 `GA_Hero_Dash`、`InputTag.Jump` 或蓝图变量名字翻译成中文后重命名；这些名字可能正被引用、反射绑定或脚本使用。游戏设置里的语言切换另见[官方 Lyra 的语言设置](/docs/06-ui/settings-mvvm#官方-lyra-已有语言设置不属于新增-mvvm)。本课程网站为中文正文，MMORPG 另有中英游戏 UI；两者不表示官方 Lyra 的每个语言或打包字体都已重新验收。

入口依据本机 `EditorSettingsViewerModule.cpp` 的 Internationalization 设置注册，以及 `InternationalizationSettingsModelDetails.cpp` 的 Editor Language / Preview Game Language 字段。这里只说明设置入口，未新增编辑器语言切换的运行验收。

## 对照 Rider 和 Target.cs 读懂构建

![Rider 中已加载 Lyra 的源文件与工程](/media/beginner/rifle/rider-definition.png)

**看图操作**：左上是工程名，中央是 LyraEquipmentDefinition.h；底部/顶部构建配置取决于 Rider 布局。先确认能打开本工程源码，不要把只打开一个文件当成已经加载 .uproject。
源码：`Source/LyraEditor.Target.cs`，本机第 12–13 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```csharp
Type = TargetType.Editor;
ExtraModuleNames.AddRange(new string[] { "LyraGame", "LyraEditor" });
```

这两行回答了构建命令中的目标名。`Type=Editor` 告诉 UBT 产物用于编辑器；`ExtraModuleNames` 指定该目标包含 `LyraGame` 和 `LyraEditor` 两个项目模块。构建的是目标，模块是目标中参与编译的组成部分。

### 将命令逐项读成人话

| 命令片段 | 作用 | 常见混淆 |
|---|---|---|
| `& '.../Build.bat'` | PowerShell 调用这个批处理文件 | 路径不是 UE 控制台指令 |
| `LyraEditor` | 选择 LyraEditor.Target.cs 对应目标 | 不是输入 LyraGame 模块名 |
| `Win64` | 目标平台 | 不是当前编辑器语言 |
| `Development` | 构建配置 | Rider 显示 Development Editor 是配置和目标类型的组合 |
| `-Project=...uproject` | 指定哪一份工程 | 同名训练副本尤其要检查完整路径 |
| `-WaitMutex` | 等待构建互斥锁 | 不负责结束 Live Coding 会话 |

`.uproject` 的插件 Enabled 与 `.Build.cs` 的模块依赖负责不同阶段：前者让项目选择插件，后者让当前模块可以使用其代码。游戏资产的创建和引用又是第三步。具体例子在[插件总览](/docs/02-architecture/plugin-atlas)。

**检查点**：能够逐项解释自己的构建命令，找到对应 Target.cs，读到 `Result: Succeeded` 后再打开工程。编译器输出很多警告时，优先定位首条实际 Error，保留其文件和行号。

## 预期结果、排障与练习

完成后应能说明当前使用的引擎路径、版本、工程路径和编辑器目标。Rider 无法解析头文件时，先查模块依赖和工程模型，避免盲目删除全部缓存。构建提示 Live Coding 活动时，先处理编辑器会话，而不是重复构建。

练习：在纸上写出“一个客户端窗口、一个专用服务器和一个独立后端”分别使用哪个目标，并说明为什么账号数据库不应由 Client 目标直接链接访问。
