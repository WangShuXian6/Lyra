## 复制之前先确认位置

下列路径均相对你的 **MMORPG 工程根目录**。在 Rider 的文件视图中右键父目录 → New → File，输入完整文件名（包括扩展名）；文件已存在时替换整个文件，不能把第二套类声明追加到末尾。页面给出的是当前教程的完整文件，代码框右上角可以复制，不含省略号占位实现。

先写 `.h` 再写 `.cpp` 便于阅读；**完成当前源码阶段的全部文件后才编译**。`*.generated.h` 由 UnrealHeaderTool 生成，不手工创建。`#include`、模块导出宏和函数签名都要保留。一个文件中出现多个类时，复制整个文件一次即可。

按 [四个源码阶段](/docs/08-mmorpg/from-zero) 使用这些文件。本组从 **00 阶段**开始使用。00–02 阶段保留当阶段的轻量 `.uproject` 和 Build.cs；03 阶段再切换到完整项目依赖。

## 逐段理解与资产连接

### 为什么这个阶段可以单独编译

MMORPG.cpp 只有模块入口，没有尚未实现的游戏类；Build.cs 只声明引擎基础模块。Target 选择产物，DefaultEngine.ini 选择引擎已有的 Entry。阶段 01/02 只扩展插件描述符，阶段 03 才用完整游戏 Build.cs 和 Config 替换骨架。

## 文件 1：DefaultEditorPerProjectUserSettings.ini

目标路径：`Config/DefaultEditorPerProjectUserSettings.ini`。原文件位于包内 `curriculum/mmorpg/skeleton/Config/DefaultEditorPerProjectUserSettings.ini`，不是需要修改的引擎文件。

<details>
<summary>展开完整文件并复制</summary>

```ini title="Config/DefaultEditorPerProjectUserSettings.ini"
[/Script/LiveCoding.LiveCodingSettings]
bEnabled=False
Startup=Manual
bAutomaticallyCompileNewClasses=False
```

</details>

using UnrealBuildTool;
public class MMORPG : ModuleRules
{
    public MMORPG(ReadOnlyTargetRules Target) : base(Target)
    {
        PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;
        PublicDependencyModuleNames.AddRange(new[] { "Core", "CoreUObject", "Engine", "InputCore" });
    }
}

## 写完后怎样确认

保存全部文件，回到当前阶段执行文件核对和 Editor 构建。文件核对只能发现缺文件、复制不完整和版本差异；`Result: Succeeded` 才说明编译成功。资产、UI 与联机行为继续按 [对应课程](/docs/08-mmorpg/from-zero) 验收。
