## 学习目标与前置条件

把空白 MMORPG 的角色配置成 UE 自带的 Manny，并理解如何切换 Quinn。角色类处理网络与玩法，PawnData 选择角色蓝图，角色蓝图设置 Mesh 与 Anim Class，主动画蓝图组织可替换的动画层。运动数据由 C++ 提供，具体姿态混合在 Anim Blueprint 中编辑。

前置条件：完成 [依赖迁移](/docs/08-mmorpg/migration)，编译 MMORPGEditor，理解 [角色与 GAS](/docs/08-mmorpg/character-gas)。本篇基于本机 UE 5.8.1，核对日期 **2026-09-13**。动画层的组织方式参考 Lyra；原始 Lyra 的全部射击动画与项目类依赖没有直接搬入新工程。

## 明确资产职责

| 资产或类 | 职责 | 后续替换位置 |
| --- | --- | --- |
| `DA_MMOExperience` | 选择本区域玩法与 PawnData | Experience 数据资产 |
| `DA_MMOPlayer` | 选择 PawnClass、输入与 AbilitySet | PawnData 数据资产 |
| `BP_MMOCharacter` | 设置继承 Mesh 的模型、偏移和动画类 | Blueprint Components / Details |
| `UMMOAnimInstance` | 游戏线程采集运动状态，管理 ASC 标签委托 | C++ 基类 |
| `ALI_MMOCharacter` | 定义 Locomotion 动画层接口 | Animation Layer Interface |
| `ABP_MMOUnarmed` | 实现无武器运动与空中姿态 | Locomotion 层图 |
| `ABP_MMOCharacter` | 组合 Linked Layer、Montage Slot、最终姿态 | 主 AnimGraph |

Lyra 的主图、Linked Layers 和线程安全更新分别承担不同职责。新实验保留这些边界：可以替换动作集合，同时继续使用相同 Pawn 初始化与动画数据接口。[Epic 的 Lyra 动画说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-in-lyra-sample-game-in-unreal-engine)可对照官方复杂射击图；本篇先把这些机制落到较小的可编辑图中。

## 建立 C++ 动画数据接口

`Source/MMORPG/Public/MMOAnimInstance.h` 与 Private 中同名 cpp 属于 MMORPG 模块。依赖 Engine 与 GameplayAbilities。两个 Anim Blueprint 都以 `MMOAnimInstance` 为父类：

~~~cpp title="MMOAnimInstance.h：动画图读取的状态"
UPROPERTY(BlueprintReadOnly, Category="MMO|Locomotion")
float GroundSpeed = 0.f;

UPROPERTY(BlueprintReadOnly, Category="MMO|Locomotion")
bool bIsFalling = false;
~~~

`NativeUpdateAnimation` 在游戏线程读取 Character 的 Velocity 与 CharacterMovement，再写入上述快照。动画图使用变量读取节点处理数值与混合，工作线程不查询世界或调用 HTTP。启用多线程动画更新后，也不能把任意 UObject 调用移动到 Blueprint Thread Safe Update 中；需要通过 Property Access 或已准备好的数据访问。

`GameplayTagPropertyMap` 沿用 Lyra 的标签到 Blueprint 属性映射思路，保存地址稳定的结构。ASC 位于 PlayerState，Avatar 是当前 Pawn；PlayerState 复制晚于 Mesh 初始化时，动画实例检查弱引用身份并重新绑定。`NativeUninitializeAnimation` 显式解除委托，使旧 Mesh 销毁、重生或切换角色后不再接收旧状态。

## 手动创建动画层接口

1. 在 Content Browser 新建 `Content/Characters/MMO` 文件夹。
2. 右键选择 **Animation → Animation Layer Interface**，命名 `ALI_MMOCharacter`。
3. 双击打开，在 My Blueprint 的 **Animation Layers** 点击添加，命名 `Locomotion`。
4. 此层不添加输入参数，保留输出 Pose。
5. 编译并保存。接口只约定层名与输入输出，不在接口里实现动画资产混合。

图：`/Game/Characters/MMO/ALI_MMOCharacter`。先在左侧定位 **Locomotion** 签名，再核对它属于 Animation Layers。此接口不放 BlendSpace 或角色运动逻辑；这些节点在下一步的实现类中配置。

## 创建无武器层实现

1. 在 Characters/MMO 右键创建 **Animation Blueprint**。
2. Parent Class 选择 **MMOAnimInstance**，Target Skeleton 选择 `SK_Mannequin`，命名 `ABP_MMOUnarmed`。
3. 打开 Class Settings，在 **Implemented Interfaces** 添加 `ALI_MMOCharacter`，编译。
4. 在 My Blueprint 打开 **Locomotion** 层图。
5. 从 Asset Browser 将 `/Game/Characters/Mannequins/Anims/Unarmed/BS_Idle_Walk_Run` 拖入图中，创建 BlendSpace Player。
6. 双击 Blend Space，在 Asset Details 核对 **Horizontal Axis = Direction**、**Vertical Axis = Speed**。回到层图读取 **Ground Speed**，连接节点显示的 **Speed** 输入（原生引脚名 **Y**）；**Direction**（原生引脚名 **X**）保留 `0.0`。不要根据引脚顺序猜测速度轴：把速度接到 Direction 仍能编译，但 Speed 会一直为零，移动时仍采样 Idle。
7. 拖入 `/Game/Characters/Mannequins/Anims/Unarmed/Jump/MM_Fall_Loop`，创建 Sequence Player，在 Details 启用 **Loop Animation**。
8. 添加 **Blend Poses by bool**，读取 **Is Falling**，接到 **Active Value**。
9. 将 Fall Loop 的 Pose 接 **True Pose**，BlendSpace 的 Pose 接 **False Pose**。
10. 将混合输出接到该层 Output Pose。保留短混合时间，避免状态变化时瞬间跳姿势。
11. 在 ABP_MMOUnarmed 的主 AnimGraph 中添加 **Local Space Ref Pose**，连 Output Pose。外部链接时使用的是 Locomotion 层；此默认主图给独立预览提供合法输出。
12. 编译、保存，查看 Compiler Results。修改某条连线后立即检查，不要带着报错继续配置主图。

## 创建主动画蓝图

1. 用相同父类和骨骼新建 `ABP_MMOCharacter`。
2. Class Settings 添加 `ALI_MMOCharacter`。
3. 在该 Blueprint 的 Locomotion 层建立相同的运动混合，作为未覆盖层时的默认实现；编译。
4. 打开主 **AnimGraph**，添加 **Linked Anim Layer**。
5. 在节点 Details 中选择 **Layer = Locomotion**，**Instance Class = ABP_MMOUnarmed**。确认指向 ALI_MMOCharacter 对应接口。
6. 添加 **Slot** 节点，Slot Name 设为 **DefaultSlot**。
7. 将 Linked Layer 的 Pose 接 Slot 的 Source，再将 Slot 输出接 Output Pose。
8. 在 Class Defaults 确认 **Use Multi Threaded Animation Update** 开启，编译保存。

## 在角色蓝图设置模型与动画类

1. 打开 `/Game/Tutorial/BP_MMOCharacter`；若打开的是 Data Only 视图，点击 **Open Full Blueprint Editor**。
2. 在 **Components** 选继承的 **Mesh**，不要另添加一套临时 Static Mesh。
3. 在 Details 的 **Skeletal Mesh Asset** 选 `SKM_Manny_Simple`。
4. **Animation Mode = Use Animation Blueprint**，**Anim Class = ABP_MMOCharacter**。
5. 选 Capsule Component 读取 **Capsule Half Height**。回 Mesh 将 Location X/Y 设 0、Z 设为该半高的负值；Rotation Yaw 设 -90，Pitch/Roll 设 0。视口确认双脚位于胶囊底部、正面与角色前方一致。
6. Mesh Collision Profile 选 **CharacterMesh**。主移动碰撞继续由 Capsule 负责。
7. 编译保存，再选 Mesh，确认模型、动画类和偏移仍保留。
8. 打开 `/Game/MMO/Pawns/DA_MMOPlayer`，确认 Pawn Class 指向此 BP_MMOCharacter；保存。
9. 打开 `DA_MMOExperience`，确认 Default Pawn Data 指向 DA_MMOPlayer；保存。

## 从图中配置走到代码行为

### 读懂速度数值怎样变成动画姿势
源码：`examples/MMORPG/Source/MMORPG/Private/MMOAnimInstance.cpp`，本机第 39–53 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```cpp
void UMMOAnimInstance::NativeUpdateAnimation(float DeltaSeconds)
{
    Super::NativeUpdateAnimation(DeltaSeconds);
    // NativeUpdateAnimation runs on the game thread before parallel graph evaluation.
    // No actor, movement or ASC reads occur in worker-thread Blueprint evaluation.
    check(IsInGameThread());
    const ACharacter* Character = Cast<ACharacter>(TryGetPawnOwner());
    GroundSpeed = Character ? Character->GetVelocity().Size2D() : 0.f;
    bIsFalling = Character && Character->GetCharacterMovement()->IsFalling();
    APlayerState* State = Character ? Character->GetPlayerState() : nullptr;
    // Replicated PlayerState can arrive after the mesh initializes. Rebind only when identity changes.
    UAbilitySystemComponent* ASC = State ? UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(State) : nullptr;
    if (ASC && ASC->GetAvatarActor() != Character) ASC = nullptr;
    InitializeWithAbilitySystem(ASC);
}
```

`TryGetPawnOwner` 找到当前 Mesh 的角色；`GetVelocity().Size2D()` 取水平速度长度，不含竖直速度；`IsFalling()` 单独描述空中状态。这样跳跃时不会因为竖直速度很大而错误选择高速奔跑动画。

代码在游戏线程读取角色、移动组件和 ASC，再让动画图读取已经整理的字段。`bUseMultiThreadedAnimationUpdate=true` 不意味着可以在工作线程动画节点里随意访问 Actor。角色/PlayerState 尚未就绪时使用安全默认值，并在对象身份改变后重新绑定。

## 预期结果、排障与练习

以 1920×1080、中等画质启动客户端。站立时播放 Idle，移动时速度驱动 Blend Space，离地时切空中姿态；第二个客户端应看到同一角色的复制移动与本地动画。重生和切换角色后，检查 Pawn、AnimInstance 与 ASC Avatar 指向新对象。

**2026-09-13 19:27–19:28 UTC，实际打包 Client 移动验证：** 在客户端 A 完成并行动画求值后，读取真正运行的 `ABP_MMOUnarmed` Linked Layer 中 BlendSpace Player。两次移动采样的 Direction/X 均为 0、Speed/Y 与 filteredY 均为 125、节点权重为 1，播放时间由约 4.190 秒推进到 6.651 秒（动画长度约 7.567 秒）。这项记录来自实际节点输入和求值结果，不只是 C++ 的 GroundSpeed 变量；详见 `verification/mmorpg-packaged-rendered-showcase.json` 的 client-1.locomotion。客户端 B 留作同场观察，此报告不声称对 B 做过相同移动采样。两个客户端的死亡重生另由 `mmorpg-packaged-smoke.json` 验证 Pawn 替换、ASC 保留和 Designer 绑定。

| 现象 | 检查位置 |
| --- | --- |
| 角色为参考姿势 | Mesh Anim Class、主 Linked Layer Instance Class、编译结果 |
| 有模型但没有材质 | 模板复制路径与依赖，是否保留 Characters/Mannequins |
| 地面一直播放空中姿态 | 胶囊落地、CharacterMovement IsFalling、场景地面碰撞 |

| 移动方向与模型朝向差 90 度 | Mesh 相对 Yaw，而不是随意改 Actor Rotation |
| 重生后标签状态不更新 | PlayerState ASC 身份、动画实例解绑、Pawn InitState 完成次序 |

| PIE 正常但包内丢模型 | PawnData 引用链、Cook 清单、模板资源是否复制进项目 Content |
