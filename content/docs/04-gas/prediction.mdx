## 学习目标与前置条件

前置：技能、Effect、网络角色。目标是理解“客户端立即响应”与“服务器确认结果”如何配合。依据本机 ASC、Jump 与 RangedWeapon 实现，核对于 2026-09-13，UE 5.8.1。

预测让所属客户端先执行允许预测的部分，再与服务器确认协调。它不等于客户端有权修改任何状态，也不自动实现所有游戏的延迟补偿或命中验证。

## 操作步骤

1. 在实验工程使用一个服务器与两个客户端。明确哪一个窗口拥有所测 Pawn。
2. 在 `ULyraGameplayAbility_Jump` 构造函数查看 `LocalPredicted`；在 ASC 中观察技能激活信息与 PredictionKey。
3. 在 `AbilitySpecInputReleased` 设置断点，观察 `InvokeReplicatedEvent(InputReleased, ...)`。本机注释说明不支持依赖 `bReplicateInputDirectly`，能力任务应通过相应事件处理输入释放。
4. 检查 `ULyraGameplayAbility_RangedWeapon::OnTargetDataReadyCallback` 中谁发送 TargetData，谁调用 CommitAbility。
5. 在 Play 的网络模拟设置中增加延迟，分别记录本地动画、远端动画、伤害生效和 UI 提示时间。网络模拟项目随编辑器界面变化，记录实际启用的参数。

## TargetData 的实际入口

本机 RangedWeapon 的客户端路径使用以下条件：

```cpp
const bool bShouldNotifyServer =
    CurrentActorInfo->IsLocallyControlled() && !CurrentActorInfo->IsNetAuthority();
```

满足时调用 `CallServerSetReplicatedTargetData`，并携带技能句柄、激活预测键和当前 ScopedPredictionKey。技能结束时移除 TargetData 委托并消费数据，防止旧数据泄漏到后续激活。

必须特别注意：本机同一函数中 `bIsTargetDataValid` 被直接设为 `true`。这份示例不能被描述成“已经实现完整服务器命中校验”。若发展成实际在线战斗，需要按自己的规则验证距离、射速、目标状态和数据可信度；射击回溯也不是仅有 PredictionKey 就自然具备。

## 属性复制与界面

LyraPlayerState 中 ASC 使用 Mixed GameplayEffect 复制模式。不同连接收到的完整 Effect 信息、标签/Cue 信息并不完全相同。制作敌人血条时使用设计好的复制属性与可见状态，不要假设每个客户端都能读取别人的完整 ActiveGameplayEffects。

界面可展示预测中的操作，但服务器拒绝后必须回到一致状态。按键失败、费用不足和冷却未结束应有清晰提示；预测失败不能靠客户端永久保留修改后的数值掩盖。

## 预期结果、排障与练习

同一操作在所属客户端响应迅速，最终权威状态在客户端一致。只在监听服务器主机正常时，检查 LocalRole 分支和网络拥有权；技能重复播放时检查本地预测与服务器确认是否重复触发非预测表现。

练习：为一个目标攻击列出三类信息：客户端意图、服务器校验材料、最终复制结果。随后设计断线、目标死亡、技能取消三个失败场景，并说明 UI 如何恢复。
