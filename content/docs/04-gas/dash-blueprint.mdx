1. 打开该技能蓝图，在 My Blueprint 中找到函数 `SelectDirectionalMontage`。先选入口与返回节点，确定数据接口。
2. 入口有 `FacingDirection`、`MovementDirection` 两个 Vector。沿纯函数线找到两次 Vector → Rotator 转换，再找到 `NormalizedDeltaRotator`。
3. 找到拆分后的 Yaw 分量和后续比较节点。逐一记下图里的阈值、符号与分支方向，不用“前后左右”四个字代替实际条件。

## 为什么归一化角度差

相同方向可以用相差 360 度的角度表示。直接相减可能把临近方向误判为大转弯；归一化的旋转差让后续方向区间判断更可靠。Vector 转 Rotator 也意味着零长度输入需要由调用方或图内逻辑给出有意义的处理。

当镜头方向与移动方向不同，动画应反映人物相对朝向的移动，不只是世界坐标的 X 正负。这个函数是阅读“移动意图 → 表现选择”的好例子，但它不承担整个冲刺位移逻辑。

### 两根同类型连线也不能交换

本机原生文本中，`NormalizedDeltaRotator` 的 **A** 接 `MovementDirection` 转成的 Rotator，**B** 接 `FacingDirection` 转成的 Rotator，即取“移动方向减面朝方向”的归一化差。两根线都是 Rotator，交换后依然可以编译，但 Yaw 符号翻转会交换侧向动画选择。

设该差的 Yaw 为 θ，图的实际分支为：

| 条件，按执行顺序判断 | Montage 成员 | BiasForwardMovement |
| --- | --- | --- |
| `abs(θ) < 45` | Dash_Fwd Montage | true |
| 否则，`abs(θ) > 135` | Dash_Bwd Montage | false |
| 否则，`θ < 0` | Dash_Left Montage | false |
| 其余 | Dash_Right Montage | false |

两个阈值都是严格比较，所以 ±45° 和 ±135° 落入侧向分支。连接证据为文本中的 `K2Node_CallFunction_14`（Delta）、`K2Node_PromotableOperator_1/2/4`（比较），以及写入 `BiasForward` 的两个 Set 节点。节点存在和函数编译通过只证明结构有效；复现时还要用同一面朝方向测试左右输入，不能从“两个引脚类型相同”推断可以互换。本表是静态图语义核对，不是本次四方向 PIE 均已通过的声明。

## 预期结果、排障与练习

用固定朝向分别输入前、后、左、右移动方向，应该能说明选中哪个 Montage 以及 BiasForward 的输出。动画选对而位移错误时，转查调用方和移动任务。

练习：挑一个区间边界的两侧角度，各代入一组方向向量。观察分支是否连续；再分析静止冲刺应采用面朝方向还是禁止激活，并将这一选择放在调用方的明确规则中。
