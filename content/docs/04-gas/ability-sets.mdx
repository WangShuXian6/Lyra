## 学习目标与前置条件

前置：[Enhanced Input](/docs/03-character/enhanced-input)。目标是能把“技能未授予”“标签不匹配”“条件不满足”分别定位。依据本机 AbilitySystem 源码，核对于 2026-09-13，UE 5.8.1。

`ULyraAbilitySet` 一次授予技能、Gameplay Effects 和 AttributeSets；`FLyraAbilitySet_GrantedHandles` 保存对应句柄，供卸装或 Feature 停用时回收。技能类只是定义，ASC 中的 AbilitySpec 才代表“这个角色拥有这个技能”。

## 操作步骤

1. 打开 `/ShooterCore/Game/AbilitySet_ShooterHero`，记录技能类、等级和 InputTag。
2. 对照 `/ShooterCore/Weapons/Rifle/AbilitySet_ShooterRifle`，区分角色基础技能和装备授予技能。
3. Rider 在 `ULyraAbilitySet::GiveToAbilitySystem` 设置断点，查看 ASC、SourceObject 和 OutGrantedHandles。
4. 查 `ALyraPlayerState::SetPawnData` 中 PawnData 的默认 AbilitySets 授予；再查 EquipmentList 中装备时授予和卸装时回收。
5. 打开一个技能 Class Defaults，记录 ActivationPolicy、ActivationGroup 和网络执行策略。不要只看 EventGraph。

### 展开一条授予记录

在 ShooterCore Content → Game 双击 **AbilitySet_ShooterHero**，在 Details 展开 **Granted Gameplay Abilities**。找到 Ability 引用为 `GA_Hero_Dash` 的行，再展开该行，完整记录 **Ability、Ability Level、Input Tag**。数组顺序不是技能 ID；练习时按 Ability 类定位这一项。下方 Granted Gameplay Effects 与 Granted Attributes 是另两种授予内容，不要把冷却 GE 随意加入这里来“启用冲刺”。

![AbilitySet_ShooterHero 的真实能力数组，展开 Dash 行的能力类、等级1与输入标签](/media/configuration/training/ability-set.png)

双击 Dash 能力后选择 **Class Defaults**，搜索并分别记录 `Activation Policy`、`Activation Group`、`Net Execution Policy`、`Instancing Policy` 与 `Cooldown Gameplay Effect Class`。前两项是 Lyra 的激活规则，后面属于 GAS 的实例、网络和效果配置。清空搜索框恢复全部字段；没有显示的字段先检查高级属性和当前父类，不凭其他版本截图猜值。

训练场副本的具体改法是打开 `AbilitySet_TrainingHero`，把已有 Dash 行的 **Ability** 改成 `/TrainingRange/Game/GA_TrainingDash`，**等级与 Input Tag 保留原值**；不要按加号再添加一份技能。技能集点 Save；若修改了 `GA_TrainingDash` 的默认值，则在能力蓝图中 Compile，无错误后 Save。重开两个资产确认引用，最后在运行 ASC 中检查只有一个训练 Dash AbilitySpec。原生准备脚本和实际 PIE 报告已经检查这项数量为 1。

## 输入标签在什么位置

本机 `Source/LyraGame/AbilitySystem/LyraAbilitySet.cpp` 的实际操作：

```cpp
AbilitySpec.GetDynamicSpecSourceTags().AddTag(AbilityToGrant.InputTag);
const FGameplayAbilitySpecHandle AbilitySpecHandle =
    LyraASC->GiveAbility(AbilitySpec);
```

这段在有权授予的执行路径内运行。客户端调用同名蓝图节点不等于具备授予权限。`SourceObject` 可指向装备实例，让装备技能找到自己的武器、弹药或其他上下文。

## 两组常见配置

| 配置 | 值 | 含义 |
|---|---|---|
| ActivationPolicy | OnInputTriggered | 输入按下时尝试激活 |
| ActivationPolicy | WhileInputActive | 持续按住且技能不活跃时继续尝试 |
| ActivationPolicy | OnSpawn | Avatar 接入后尝试激活 |
| ActivationGroup | Independent | 不参与独占冲突 |
| ActivationGroup | Exclusive_Replaceable | 可被其他独占技能替换 |
| ActivationGroup | Exclusive_Blocking | 阻止其他独占技能 |

独占组与标签条件是两套协作规则。`ULyraAbilityTagRelationshipMapping` 能由能力标签扩展要阻止/取消的标签，以及激活需要/禁止的标签。冷却或费用失败不应误判为独占组问题。

## 把授予代码和输入匹配代码放在一起读

源码：`Source/LyraGame/AbilitySystem/LyraAbilitySet.cpp`，本机第 114–120 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```cpp
ULyraGameplayAbility* AbilityCDO = AbilityToGrant.Ability->GetDefaultObject<ULyraGameplayAbility>();

FGameplayAbilitySpec AbilitySpec(AbilityCDO, AbilityToGrant.AbilityLevel);
AbilitySpec.SourceObject = SourceObject;
AbilitySpec.GetDynamicSpecSourceTags().AddTag(AbilityToGrant.InputTag);

const FGameplayAbilitySpecHandle AbilitySpecHandle = LyraASC->GiveAbility(AbilitySpec);
```

### 一项配置怎样变成 AbilitySpec

1. 从 `AbilityToGrant.Ability` 指定的类读取默认对象。
2. `FGameplayAbilitySpec` 记录这个技能及授予等级；它不是一次已经完成的技能攻击。
3. `SourceObject` 保存来源，例如装备授予时可关联装备实例。
4. 将配置中的 InputTag 放进 Spec 的动态来源标签集合。
5. `GiveAbility` 交给 ASC 管理，返回句柄；外层保存句柄以后才能回收。

`GiveToAbilitySystem` 开头还检查 ASC Owner 的权威性，非权威端会返回。读取这一段不能跳过外层条件，照抄其中一行到客户端按键函数并不能得到正确授予流程。
源码：`Source/LyraGame/AbilitySystem/LyraAbilitySystemComponent.cpp`，本机第 186–200 行。下面是实际节选；在 Rider 中按文件名和函数名定位，完整上下文以源文件为准。

```cpp
void ULyraAbilitySystemComponent::AbilityInputTagPressed(const FGameplayTag& InputTag)
{
	if (InputTag.IsValid())
	{
		for (const FGameplayAbilitySpec& AbilitySpec : ActivatableAbilities.Items)
		{
			if (AbilitySpec.Ability && (AbilitySpec.GetDynamicSpecSourceTags().HasTagExact(InputTag)))
			{
				InputPressedSpecHandles.AddUnique(AbilitySpec.Handle);
				InputHeldSpecHandles.AddUnique(AbilitySpec.Handle);
			}
		}
	}
}

```

### 为什么输入标签拼错会“按了没反应”

循环读的是 ASC **已经授予**的能力；`HasTagExact` 用当前输入标签匹配 Spec 标签。匹配后只把句柄记到本帧按下/持续按住列表，真正尝试激活在 `ProcessAbilityInput`。所以这两个代码块刚好对应“授予时写标签”和“输入时按标签找能力”。

对照本章 AbilitySet 截图，定位 Dash 项，读 Ability、Ability Level、Input Tag；再用输入章节的 InputConfig 对齐。Activation Policy 决定按下/持续/生成等触发策略，Activation Group 控制并发关系，Net Execution Policy 决定网络执行方式，它们不是同一个下拉框的不同名字。

**检查点**：能从一项 AbilitySet 写出完整链：字段 → Spec 标签 → 输入匹配 → 尝试激活。想停用整组技能时保存和回收授予句柄，不要只把数组从资产里删掉后假定当前 ASC 已同步移除。

## 预期结果、排障与练习

技能可在 ASC 调试信息中找到，输入标签与动态来源标签完全一致。失败时检查本机定义的 `Ability.ActivateFail.Cost`、`Cooldown`、`TagsBlocked`、`TagsMissing`、`ActivationGroup` 等原因，再进入对应函数断点。

练习：设计一个引导读条技能，使移动或另一个独占技能能打断它。写清激活组、标签与 EndAbility 清理，而不通过每帧扫描“其他技能是否在运行”来实现。更多官方概念见 [Abilities in Lyra](https://dev.epicgames.com/documentation/unreal-engine/abilities-in-lyra-in-unreal-engine)。
